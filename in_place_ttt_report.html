项目阅读报告

In-Place Test-Time Training

这个仓库把论文中的 In-Place TTT 落到 Qwen3 和 LLaMA 的 HuggingFace 模型实现中： 不新增外部记忆或替换 Attention，而是在选中 Transformer 层的 MLP down_proj 上实现 fast weight 更新。

训练路径：hf_models/ 推理路径：inference_model/ 论文：papers/sections/approach.tex
项目结构仓库模块与运行链路 算法主线论文方法到公式 关键改动代码位置和职责 注意点训练、推理、边界

项目整体结构

仓库不是从零实现一个训练框架，而是在 VeOmni/HuggingFace 模型栈上增加 In-Place TTT 能力。 入口脚本负责训练、转换和评测；关键算法主要集中在自定义模型文件，而不是训练循环本身。

4 条主链路 训练、checkpoint 转换、推理、OpenCompass/RULER 评测。
2 套模型实现 hf_models/ 用于训练，inference_model/ 用于 TTT-aware 推理。
1 个算法落点 选中层的 MLP down_proj，即论文里的 W_down。

训练链路

  • train.sh：封装 torchrun，自动选择 GPU/NPU 并注入分布式参数。
  • tasks/train_torch.py：强制 HuggingFace backend，提前导入 hf_models 注册自定义模型，再调用 VeOmni 构建模型、数据和优化器。
  • configs/pretrain/*.yaml：把 ttt_layers、ttt_mode、ttt_lr、ttt_chunk 注入模型配置。

推理与评测链路

  • inference_model/：注册推理版 Qwen3/LLaMA，并引入 TTTDynamicCache 保存 fast weight 状态。
  • eval.sh 与 eval_config/：通过 OpenCompass 跑 RULER 长上下文评测。
  • scripts/merge_dcp_to_hf.py：把 VeOmni DCP checkpoint 转成 HuggingFace 格式。

论文算法主线

论文的核心判断是：不要替换 Attention，也不要加独立外部记忆，而是复用 Transformer MLP。 gated MLP 的 W_gate 和 W_up 继续作为慢权重，W_down 被视为 fast weights， 在推理时随输入 chunk 更新。

Z = act(H · W_gate^T) ⊙ (H · W_up^T)
O_i = Z_i · (W_down^(i))^T
W_down^(i+1) = W_down^(i) + η · V_i^T · Z_i

其中 V 不是传统 TTT 的当前 token 重构目标，而是由输入 embedding 或隐藏状态经 Conv1D 和投影得到的 LM-aligned target，目标是让 fast weights 存储对未来 token 预测有用的信息。

论文到实现的对应关系

论文概念 代码实现 含义
W_down fast weights self.down_proj.weight MLP 最终投影矩阵被复用为可在线更新的状态。
Z key / intermediate activation h = act(gate_proj(x)) * up_proj(x) SwiGLU 中间激活，作为更新里的 key。
V_hat = Conv1D(X0) W_target ttt_conv + ttt_proj 生成语言建模对齐的 value target。
Chunk-wise update padding()、rearrange()、cumsum() 训练时一次性并行计算 chunk 前缀更新；推理时保存跨步状态。

in-place-ttt 的关键算法改动在哪里

最关键的算法改动集中在四类文件：训练模型、推理模型、配置、模型注册/入口。真正改变数学行为的是 modeling_*.py 里的 MLP 和 decoder layer；训练循环只是把这些模型接入 VeOmni。

训练模型
hf_models/hf_qwen3/modeling_qwen3.py:72-138 和 hf_models/hf_llama/modeling_llama.py:153-232。 这里给 MLP 增加 layer_idx、ttt_conv、ttt_proj、ttt_lr、ttt_chunk， 并在 forward(x, t) 中按 chunk 计算 d_down_proj 和前缀累积的有效 down_proj。
训练层间传参
hf_models/hf_qwen3/modeling_qwen3.py:288-337 和 hf_models/hf_qwen3/modeling_qwen3.py:475-550。 decoder layer 判断当前层是否是 TTT layer；ttt_target=hidden_states 时默认用 MLP 前的 hidden states， ttt_target=input_embed 时由模型级方法传入输入 embedding。
推理状态
inference_model/hf_qwen3/modeling_qwen3.py:52-59 定义 TTTDynamicCache， inference_model/hf_qwen3/modeling_qwen3.py:117-152 让 MLP 接收 past_w 并返回更新后的权重， inference_model/hf_qwen3/modeling_qwen3.py:353-376 保存未满 chunk 的 past_h/past_t 和 present_w。

inference_model/hf_qwen3/modeling_qwen3.py:575-587 和 LLaMA 对应实现会在 TTT 模式下强制使用 TTTDynamicCache，并限制生成 batch size 为 1。这是为了让在线 fast weight 状态在自回归生成中语义清晰。
配置开关

入口与注册
tasks/train_torch.py:27-36 先导入 hf_models 覆盖 AutoModel 注册； hf_models/*/__init__.py 注册自定义配置和模型； inference_model/*/__init__.py 注册推理版模型。
核心一

MLP 内部复用 fast weights

标准 MLP 原本只做 down_proj(h)；TTT layer 中改为先根据 chunk 前缀更新得到有效权重， 再用这个有效权重投影当前 chunk。

核心二

LM-aligned target

ttt_conv 是 depthwise Conv1D，ttt_proj 是 hidden-size 方阵投影； 两者共同对应论文中的 Conv1D(X0) W_target。

核心三

训练与推理分离实现

训练版用 cumsum 批量形成 chunk 前缀；推理版显式循环并把 past_w、未满 chunk 的尾部状态放进 cache。

端到端工作流

1. 数据 提供 VeOmni 兼容的 processed dataset，常用 plaintext 和 content_split。
2. 构建模型 build_foundation_model(..., config_kwargs=args.model.foundation) 注入 TTT 参数。
3. 训练 VeOmni/FSDP2 训练；forward 中的 TTT MLP 参与反向传播，学习 ttt_conv 和 ttt_proj。
4. 转换 merge_dcp_to_hf.py 将 DCP 权重按 shard 输出为 HuggingFace checkpoint。
5. 推理评测 inference_model 注册 TTT cache；eval.sh 跑 RULER sweep。

阅读结论与注意点

  • 算法关键点非常集中：优先读 hf_models/hf_qwen3/modeling_qwen3.py 的 Qwen3MLP， 再读推理版 inference_model/hf_qwen3/modeling_qwen3.py 的 cache 处理。LLaMA 版本基本是同构移植。
  • 论文与代码映射清晰：论文的 W_down、Z、V_hat、chunk update 都能在 MLP forward 中直接找到对应实现。
  • 配置决定启用范围：ttt_layers 控制哪些层启用，推荐配置是每隔 6 层启用一次； ttt_chunk 控制更新粒度，README 推荐值为 4096，配置类默认值为 8192。
  • 推理版有状态语义：生成过程中 fast weights 会随上下文持续变化，所以实现用自定义 cache 保存 past_h、past_t、past_w，且当前只支持 batch size 1 的 TTT generation。
  • 需要复核的工程边界：论文附录提到长上下文评测时有 update delta clipping，但当前仓库的 inference_model/ 中没有明显的 clipping 实现；如果复现实验，需要确认 checkpoint/config 或外部推理栈是否另行处理。
实现细节提示： 代码中 ttt_conv 使用 kernel_size=5, padding=2, groups=hidden_size。 由于当前 chunk 的更新不会用于当前 chunk 的输出，而是用于后续 chunk，这保持了 chunk 级 apply-then-update 语义。 如果要讨论严格逐 token 因果，需要单独审查 Conv1D padding 与目标构造策略。
